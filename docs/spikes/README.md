# Spikes técnicos

Esta carpeta guarda los spikes acotados en tiempo que validan decisiones antes de implementarlas.

Cada spike debe incluir:

- Hipótesis y pregunta a responder.
- Configuración probada (versiones, variables, comandos).
- Resultados medidos (cold start, latencia, límites, errores).
- Decisión tomada y consecuencias.
- Enlaces a issues/PRs relacionados.

El primer spike previsto es `vercel-express.md` en la Fase 0: Express como función serverless, Postgres pooled, cookies same-origin, cold start, límite de body y módulos nativos.
